# 新規プロジェクトの聞き取り(1 問 1 答)

ルールの原本は共通設定(`AI-CONFIG.md`)の「新規プロジェクトの聞き取り」。質問の台本は ai-config の `ai-systems/project-intake-questions.md`。

## いつ使うか

本人の発言に次が含まれ、**既存のどのリポジトリの作業にも収まらない**とき。

- 「新しいプロジェクト」「新規プロジェクト」「プロジェクトを作りたい / 立ち上げたい」
- 「新しいリポジトリ」「新しく〇〇を作りたい」「〇〇というサービス / アプリ / ツールを作りたい」
- 「〇〇で稼ぎたい」「〇〇を始めたい」

既存リポジトリの機能追加・不具合修正には使わない。**迷ったら Q0 で確かめる。**

## 大原則

**1 回の返答で聞くのは 1 問だけ。** まとめて出さない。これは「確認質問を極力しない」という共通ルールの唯一の例外。

## 手順

1. **Q0(迷ったときだけ)**: 新しいプロジェクトか、既存の中の話かを確かめる。既存の中なら聞き取りはせず、いつもどおり進める
2. **置き場所を決める**
   - ここが `ai-config` なら: `projects/_template/` を `projects/<スラッグ>/` にコピーする
   - ここが `ai-config` 以外なら: そのまま聞き取りを続けてよい。答えは手元にメモし、終わったら `/ai-config-memo`(`kind: project`)で受信箱へ送る。ai-config 側が `projects/` に企画書を作る。まだ何も話していない段階なら「この話は ai-config で計画から始めるね」と 1 行伝えて受信箱へ送るだけでもよい
3. **1 問ずつ聞く**
   - 選択肢を 3〜4 個添える。**「決めていない / 任せる」を必ず 1 つ入れる**
   - 「任せる」が返ったら AI が仮で決め、`仮:` を付けて記録し、次の問へ進む。**そこで止まらない**
   - 答えが返るたびに `intake.md` へ追記して保存する(会話が切れても再開できるように)。`next` の欄を次の問に書き換える
   - 前の答えで不要になった問は飛ばす
4. **最大 12 問で打ち切る。** 残りは仮置きして企画書を書く。本人が「もういいから作って」と言ったらその場で打ち切る
5. **企画書を書く**(`charter.md`)。目的 / 成功の数字 / 作るもの / 元手 / リスク / 最初の 3 手 / 仮で置いたもの / やめる条件
6. **後始末**(確認は取らない)
   - `projects/README.md` の一覧に 1 行足す
   - 新しいリポジトリを作ると決まったら `ai-systems/open-decisions.md` の第 4 節に `A-`(本人の作業)を足す。**AI は勝手にリポジトリを作らない**
   - 収益を狙うものは `ai-systems/monetization-strategies.md` に節を足す
   - 残った判断は `D-` として台帳へ積む。その場で追撃しない

## 聞く順番(6 段階)

| 段階 | 問 |
|------|----|
| 1. 目的 | Q1 いちばん達成したいことは?(お金 / 時間 / 学習・実績 / 生活) |
| 2. 出口 | Q2 いつまでに、何がいくつになったら成功? |
| 3. 中身 | Q3 具体的に何を作る? / Q4 使うのは本人だけ? 他人にも出す? |
| 4. 元手 | Q5 かけられるお金と時間の上限は? |
| 5. 危険 | Q6 他人のデータ・外部の規約・お金のやり取りは絡む? |
| 6. 置き場 | Q7 新しいリポジトリ? 既存のどれか? |

Q8 以降は答えに応じて足す。全部は聞かない。

## しないこと

- 1 回の返答に複数の問を詰め込まない
- 聞き取りが終わる前にコードを書き始めない(調査・既存の確認はしてよい)
- 空欄のまま企画書に残さない(必ず `仮:` を書く)
- 「分からない」を責めない
