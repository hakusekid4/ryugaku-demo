# チケットを 1 枚片付ける(run-ticket)

*原典は Matt Pocock の `implement`(MIT ライセンス)。チケットの置き場と `/goal` に合わせて書き直した。流れ全体の説明は ai-config の `ai-systems/dev-flow.md`。*

## /goal との組み合わせ

`/goal` は Claude Code の組み込みコマンド。条件を 1 つ置くと、Claude は止まる前に毎回その条件を確かめ、満たすまで作業を続ける。チケットの「/goal」欄の 1 行を本人が貼れば、このスキルの手順で通るまで回る。

```
/goal docs/plans/<スラッグ>/tickets/01-<スラッグ>.md を /run-ticket の手順で実装し、「完了条件」のコマンドがすべて通り状態が done になっている。または /run-ticket の「止まってよいとき」(同じ失敗 3 回・着手から 2 時間など)に当たり、状態が ready-for-human になって理由が記録されている
```

`/goal clear` で途中で止められる。定期起動から回すときは、指示文に `/run-ticket docs/plans/<スラッグ>` と書く(前線の 1 枚を取る)。

## 手順

1. **1 枚選ぶ**: 引数がチケットのファイルならそれ。フォルダなら `python .claude/tools/tickets.py frontier docs/plans/<スラッグ>` で**前線**(状態が `ready-for-agent` で、依存がすべて `done`)を出し、最初の 1 枚を取る(ai-config では `scripts/tickets.py`)。前線が空なら、何が何待ちかを 1〜3 行で報告して終わる
2. **着手を記す**: 状態を `in-progress` にし、「記録」に着手の日時(日本時間)を書いて保存する(他のセッションと取り合わないため。2 時間の上限もここから数える)。複数セッションが動くリポジトリなら、ここで 1 回コミットして push する
3. **読む**: チケット・元の仕様書・`GLOSSARY.md`・関係する `docs/adr/`
4. **作る**: `/tdd` の決まりで、仕様書の継ぎ目に沿って RED → GREEN を回す。テストは 1 ファイルずつ頻繁に走らせる
5. **完了条件を全部走らせる**: チケットの「完了条件」のコマンドを書いてあるとおりに実行し、出力の要点(終了コード・数字)を「記録」に貼る。最後にテスト全体を 1 回走らせる
6. **見直す**: 差分を自分で読み直す。重いもの・大きいものは `/code-review` を使う。作り直し(リファクタリング)はここでやり、終わったら完了条件を走らせ直す
7. **閉じる**: 状態を `done` にし、「記録」に `- 閉じた: <日時(日本時間)>。<完了条件の結果・コミット>` の 1 行を書く(週の枚数はこの行から数える。`scripts/ticket_counts.py`)。`tickets/README.md` の一覧の状態も直す。コミットして push する
8. **その日のページに書く**(2026-10-05 本人回答。作業フィードはやめた): `/daily-page` があれば、そのセッションのページの「今日やったこと」に「チケット NN「<題>」を done にした」、「次にやること」に次の前線を足して書き換える(無ければこの手順は飛ばす)。止まったときは「本人に要ること」に理由と次の案を書き、**`PushNotification` でスマホに 1 本**送る
9. **報告**: 1〜3 行。終わったチケット・次の前線・本人確認が要るもの

## 止まってよいとき(/goal の条件を満たさずに終わってよいとき)

次のどれかに当たったら、作業を止めてチケットの状態を `ready-for-human` にし、「記録」に `- 止めた: <日時(日本時間)>。<理由と次の案>` の 1 行を書いて報告する(手順 8 のとおりページとスマホへも)。**黙って条件を緩めない。テストを消したり飛ばしたりしない。**

- 本人の判断・作業が要る(お金・外部への投稿・削除・履歴の書き換え、台帳に積むべき論点)。判断は ai-config の台帳へ積む(ai-config 以外からは `/ai-config-memo` の `kind: question`)
- 完了条件そのものが誤っている・確かめようがない(データがまだ無い、など)
- 同じ失敗を 3 回続けて直せなかった(原因と試したことを書く)
- **着手から 2 時間たった**(2026-10-05 本人回答。同じ失敗 3 回と、先に当たったほうで止める)。残りの見込みと、割るならどう割るかを書く
- チケットが 1 セッションに収まらないと分かった(割り方の案を書いて `/to-tickets` に戻す)

## しないこと

- 前線でない(依存が終わっていない)チケットに手を付ける
- 完了条件のコマンドを走らせずに done にする
- 完了条件に合わせてテストや閾値を書き換える(書き換えるべきだと思ったら、止まって理由を書く)
