# やり取りの最後の自動化探索

ルールの原本は共通設定(`AI-CONFIG.md`)の「やり取りの最後の自動化探索」。ここは手順だけ。

## いつ使うか

**手を動かした(ファイルを変えた・コマンドを実行した・調べ物をした)やり取りの最後に、毎回。**

使わなくてよいのは、質問に答えただけのやり取り / 直前に探索済みで状況が変わっていないとき / 自動化そのものを実装していたやり取り。

## 手順

1. **先に台帳を読む**(重複を挙げないため)
   - このリポジトリが `ai-config` なら `ai-systems/automation-backlog.md` の第 3・4・5 節
   - それ以外なら `ai-config-inbox/` の過去の `kind: automation` を見る
2. **今回のやり取りに 6 つの問いを当てる**。最大 3 件まで挙げる。0 件でよい
   1. 同じ手順を前にもやったか → スクリプト化・スキル化
   2. 毎回「やっておいて」と頼まれる形か → 定期実行(GitHub Actions / Routine)
   3. 手で貼った・写した数字やテキストがあったか → 生成の自動化
   4. 「次はここを見る」と口で引き継いだか → ファイル化
   5. 同じ失敗・同じ確認を繰り返しているか → テスト・ガード
   6. 本人の手作業が残っているか → 手順の短縮・代行の可否
3. **1 件ずつ A / B / C に分ける**
   - **A(即やる)**: 外部への投稿・応募・送金・発注なし / 新しい費用・鍵・外部アカウントなし / 30 分以内 / 壊れても既存の動きを止めない、を**すべて**満たす
   - **B(判断が要る)**: A を 1 つでも外れる
   - **C(見送り)**: 月 1 回未満しか起きない / 作るほうが遅い / 効果が測れない
4. **A はその場で作ってコミットする。** 本人に確認は取らない
5. **記録する**
   - `ai-config` なら: A は台帳の第 4 節、B は第 3 節、C は第 5 節へ直接書く
   - それ以外のリポジトリなら: B と、A で実装したものを `/ai-config-memo`(`kind: automation`)で `ai-config-inbox/` へ送る
6. **本人には 1〜3 行で伝える。** 0 件なら「自動化の探索: 今回は無し。」の 1 行

## B を書くときの欄(7 つ。空欄にしない)

ID / 何を自動化するか / 今の手間(月に何回・1 回何分・誰が。**数字必須**)/ 作るもの(種類と置き場所)/ 要るもの(費用・鍵・本人の作業)/ なぜ即やらないか / 状態

## しないこと

- 同じ案を毎回挙げ直さない
- 数字の無い案を「やるべき」と書かない
- 本人にその場で「自動化していい?」と聞かない(B は台帳へ積む。週次まとめでまとめて出る)
- 自動化のために共通設定の禁止事項を緩めない
