# チケットに分ける(to-tickets)

*原典は Matt Pocock の `to-tickets`(旧名 `to-issues`、MIT ライセンス)。置き場をこのリポジトリ内の Markdown にし(理由は ai-config の `docs/adr/0001-local-markdown-tickets.md`)、Claude Code の `/goal`(条件を満たすまで作業を続けさせる組み込みコマンド)で回せる形にした。流れ全体の説明は ai-config の `ai-systems/dev-flow.md`。*

## 1. 材料を集める

会話にあるものから始める。引数で `docs/plans/<スラッグ>/spec.md` などを渡されたら全文を読む。`GLOSSARY.md` と `docs/adr/` も読み、チケットの題と本文は用語集の言葉で書く。

コードを読み、**先に下ごしらえ(prefactor)すると実装が楽になる所**を探す。「変更を簡単にしてから、簡単な変更をする」。下ごしらえは最初のチケットにする。

## 2. 垂直スライスに切る

- 1 枚が、データ → 処理 → 出力 → テストまで**細くても全部の層を貫く**(縦切り)。「DB だけ」「API だけ」の横切りにしない
- 1 枚終わるごとに、それだけで**動作を見せられる・確かめられる**
- 1 枚は**まっさらな 1 セッションで終わる大きさ**
- 各チケットに**先に終わっている必要があるチケット**(blocked by)を書く。無ければ「なし(すぐ着手できる)」

**例外: 広い作り替え**(列名の変更・共通の型の変更など、1 か所直すと全体が壊れるもの)は縦切りにせず、**足す → 移す → 消す**の順に並べる。

1. 足す: 新しい形を古い形の横に足す(何も壊れない)
2. 移す: 呼び出し元を、パッケージやフォルダ単位の束で新しい形へ移す。束ごとに 1 枚(1 に依存)
3. 消す: 呼び出し元が無くなったら古い形を消す(2 の全部に依存)

## 3. 完了条件を「機械で確かめられる形」で書く

`/goal` は、条件を満たしたかを Claude 自身が判定して、満たすまで止まらない。**判定があいまいだと、止まるべき所で止まらないか、早く止まる。**だから完了条件は次のどれかで書く。

- コマンドの終了コード: 「`python -m pytest tests/test_late_money.py` が通る」
- 数値の閾値: 「`python scripts/gate.py judge` の出力で `delta_nats` が 0 以上」
- ファイルの存在と中身: 「`reports/late_money.json` があり、`races` が 100 件以上」
- 人の目が要るものは「本人確認: 〜」と書き、**/goal の条件には入れない**(そこは止まって報告する)

## 4. 本人に見せる(待たずに進める)

番号付きの一覧で出す。各チケットに「題 / 依存 / できるようになること」。最後に 1 行「粒度・依存の向き・まとめる/割るの直しがあれば言って。無ければこのまま回す」。**承認待ちで止まらない。**書いてから直すほうが速い。

## 5. 書く

`docs/plans/<スラッグ>/tickets/NN-<スラッグ>.md`。`01` から依存の順(先に要るものほど小さい番号)。**1 枚 1 ファイル。まとめて 1 ファイルにしない。**

```md
# 01: <題>

- 状態: ready-for-agent
- 依存: なし(すぐ着手できる)
- 元: docs/plans/<スラッグ>/spec.md のストーリー 1・3

## 作るもの
使う人から見た、端から端までの振る舞い。層ごとの実装の羅列にしない。

## 完了条件
- [ ] `python -m pytest tests/test_xxx.py` が通る
- [ ] `python scripts/xxx.py --check` の終了コードが 0
- [ ] 本人確認: (あれば。/goal には入れない)

## /goal(貼るだけで回る)
/goal docs/plans/<スラッグ>/tickets/01-<スラッグ>.md を /run-ticket の手順で実装し、「完了条件」のコマンドがすべて通り、状態が done になっている

## 記録
(実装した AI が追記する)
```

状態は `ready-for-agent`(AI が着手してよい)/ `ready-for-human`(本人の作業・判断が要る)/ `in-progress` / `done` / `wontfix`(やらない)のどれか。

本文にファイルパスやコード片は書かない(完了条件のコマンドは例外)。試作で決まった型やデータの形だけは、要る部分を載せて「試作から」と注記してよい。

最後に `docs/plans/<スラッグ>/tickets/README.md` に一覧(番号・題・依存・状態)を書く。

書き終えたら `python .claude/tools/tickets.py lint docs/plans/<スラッグ>` を走らせ、問題 0 件にする(状態の綴り・無い番号への依存・循環・コマンドの無い完了条件を見る。ai-config では `scripts/tickets.py`)。

## 6. 回し方を伝える

本人への報告は次の 3 行で足りる。

- 何枚に分けたか・最初に着手できるもの(前線 = 依存がすべて done のもの)
- 最初の 1 枚の `/goal` の 1 行(そのまま貼れば回る)
- 定期起動(Routine)で回すなら `/run-ticket docs/plans/<スラッグ>` を指示文にすればよいこと
